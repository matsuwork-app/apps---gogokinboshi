# LINE認証・ターン制得点入力 実装計画

## 目的

- アプリ全体をLINE Loginで保護し、管理者1名が承認した利用者だけ閲覧・入力できるようにする。
- 試合単位の作成・対戦チーム選択を廃止し、チーム編成が変わるまでを1つの「ターン」として全チームの個人得点を同じ画面で入力する。
- 既存の試合・得点履歴は保持し、ランキングに引き続き合算する。
- 出場時間、出場中・休憩中、キックオフ・再開の操作を新方式から除き、繰り返し使える独立したカウントダウンタイマーを追加する。

## 確定仕様

### 認証・権限

- Supabase AuthのCustom OIDC ProviderとしてLINE Loginを設定する。
- アプリ内の権限は `admin` と `member` の2種類、状態は `pending` / `approved` / `revoked` とする。
- 管理者は環境変数 `LINE_ADMIN_USER_ID` と一致するLINEユーザー1名だけ。最初のアクセス者を自動管理者にはしない。
- 初回LINEログイン時は一般利用者を `pending` で登録し、管理者が承認する。
- `approved` の利用者はアプリ全体の閲覧・得点入力・イベント管理を行える。利用者の承認・停止だけは管理者専用とする。
- 未ログインは `/login`、未承認は `/pending` へ誘導する。
- Next.js Proxyはセッション更新と早期リダイレクトに使い、各Server Action/APIでは必ず再度認可する。
- Supabase RLSから匿名読み取りを外し、承認済みユーザーのみ読み取り可能にする。書き込みは既存どおりServer Action + service roleを利用し、Action入口で承認状態を検証する。

### ターンと得点

- `event_turns`: イベント内の第1、第2…ターンを保持する。
- `turn_team_members`: 各ターン開始時点のチーム所属をスナップショットとして保持する。
- イベント作成時に第1ターンも同時作成する。
- チームを組み替えると新しいターンを作り、過去ターンの所属と得点は変更しない。
- 既存 `goals` に `event_turn_id` を追加し、旧データは `match_id`、新データは `event_turn_id` のどちらか一方に所属させる。
- 新方式では対戦カード・試合結果は保存しない。全チーム・全メンバーを1画面に並べ、個人の加点・減点を行う。
- 各メンバーに「このターンの得点」と小さな灰色の「本日累計」を常時表示する。

### タイマー

- ターン画面に5分・7分・10分のプリセットと開始/一時停止/リセットを設ける。
- タイマーはブラウザ内の補助機能で、得点やDB状態とは連動しない。
- 同じターン内で何度でもリセットして利用できる。

### ランキング

- 旧試合得点と新ターン得点を合算する。
- 参加回数はイベント参加者として登録されている日を1回として数える。
- 出場時間は新規記録・画面表示・順位評価から除外する。旧データ自体は削除しない。

## データベース実装

1. `app_users`、`event_turns`、`turn_team_members` を追加する。
2. `goals.match_id` をnullable化し、`goals.event_turn_id` を追加する。
3. 得点が旧試合か新ターンの厳密に一方へ所属するCHECK制約を付ける。
4. `(event_turn_id, member_id)` がターン所属に存在する複合外部キーを付ける。
5. 既存イベントには現在の `event_team_members` から第1ターンのスナップショットを作る。
6. `create_event_with_teams` をイベント・チーム・参加者・第1ターンの原子的作成へ更新する。
7. `create_event_turn(event_id, assignments)` RPCを追加し、イベント単位advisory lock、参加者の一意割当、全チーム非空を保証する。
8. `get_rankings` を旧試合得点と新ターン得点の双方に対応させ、匿名実行権限を外す。
9. 全テーブルの匿名SELECT権限と `public_read` policyを除去し、承認済みユーザー向けSELECT policyへ置き換える。

## アプリ実装

1. Supabase SSRクライアントのセッション更新Proxyを追加する。
2. `getCurrentAppUser`、`requireApprovedUser`、`requireAdminUser` のDALを追加する。
3. `/login`、`/auth/callback`、`/pending`、`/admin/access`、ログアウトを追加する。
4. 既存の管理パスコードUI・Action依存を承認済みユーザー認可へ置き換える。
5. イベント詳細をターン一覧と「最新ターンを開く」中心へ変更する。
6. `/events/[id]/turns/[turnId]` に全チーム得点入力とタイマーを実装する。
7. チーム編集は保存時に新ターンを作る方式へ変更する。
8. 旧試合ページは既存履歴確認用として残し、新しい試合作成導線は撤去する。
9. ランキング・文言・メタデータから出場時間を削除する。

## 安全なリリース手順

1. ローカルDB検証、単体テスト、型検査、ビルドを通す。
2. Previewへデプロイし、LINE設定前は既存本番を切り替えない。
3. LINE DevelopersでWebアプリ用LINE Loginチャネルを作成する。
4. Supabase DashboardでCustom OIDC Provider `line` を設定する。
5. Vercelに `NEXT_PUBLIC_SITE_URL`、`LINE_ADMIN_USER_ID`、認証切替フラグを設定する。
6. Previewで管理者ログイン、未承認画面、承認、ターン得点、組み替え、ランキングをPlaywrightと実ブラウザで確認する。
7. DB migration適用後に本番へ昇格し、匿名アクセスが遮断されていることを確認する。

## テスト受け入れ条件

- 未ログイン利用者がランキングを含むアプリ本体を閲覧できない。
- 未承認利用者は待機画面だけを閲覧できる。
- 管理者1名だけが利用者の承認・停止を行える。
- 2〜4チームで第1ターンを作成でき、全員がちょうど1チームに所属する。
- 1画面で全チームの個人得点を増減でき、本日累計が即時反映される。
- 組み替え後は第2ターンになり、過去ターン得点と所属が保持される。
- 5/7/10分タイマーを開始・一時停止・リセットし、繰り返し使える。
- ランキングが旧試合得点と新ターン得点を合算し、参加回数をイベント単位で数える。
- DB migration verifier、Vitest、TypeScript、Next build、Playwright主要フローが成功する。
